# План реализации

Задание: `task/task.md`. Макет: `task/design.drawio.xml`. Решения: `docs/adr/`. Правила: `CLAUDE.md`.

## Как работаем

```
main ── step/0-conventions ── step/1-foundation ── step/2-core ── step/3-polish ── step/4-bonus
```

- Каждая ветка создаётся от предыдущей; внутри — атомарные коммиты. Автор полирует, мерджит в `main`
  и ставит тег `step/N` (задание: «каждый этап — отдельный коммит с тегом» → при мердже шаг сквошится
  или тегируется merge-коммит — на усмотрение автора).
- Задачи внутри шага идут в указанном порядке: сначала чистая логика с тестами, потом UI.
- Каждая задача заканчивается записью в `docs/ai-log.md`.
- Шаг закрыт = выполнен чек-лист «Приёмка» + зелёные `typecheck`, `lint`, `test`, `build`, `size`.

Продукт по макету: приложение «Бюджетница», один экран. Шапка: название, строка поиска, индикатор
соединения. Слева таблица, справа дерево («Свернуть все / Развернуть все»), у панелей собственный скролл.
Ниже 1280px — одна панель и переключатель «Таблица / Дерево» в шапке.

## Шаг 1. Foundation — `step/1-foundation`

Цель: монорепо, mock-API, валидируемый кэшируемый запрос, интерактивное дерево, три состояния.

**1.1 Scaffold монорепо.** Корневой `package.json` (workspaces, скрипты `dev/test/lint/typecheck/build/size`),
`tsconfig.base.json` (strict, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`), ESLint flat + Prettier,
запрет `style`-пропа и направления импортов (`no-restricted-imports`), Vitest. `apps/client` — Vite + React + TS,
алиас `@/` (tsconfig `paths` + `resolve.alias`), dev-прокси `/api` и `/ws` на сервер. `scripts/size.mjs` —
gzip-сумма JS+CSS, порог 200 КБ.

**1.2 Контракты.** `packages/contracts`: `OrgNodeSchema` (`id`, `name`, `parentId: string | null`, `headcount`
int ≥ 0, `budget` int ≥ 0, `performance` 0–100, `updatedAt` ISO), `OrgTreeResponseSchema`. Тесты на схему
(валидный, лишние поля, performance вне диапазона, не массив).

**1.3 Сервер.** Fastify: `GET /api/org-tree` → плоский массив, `ETag: "v<version>"`, `Cache-Control: no-cache`,
ответ `304` по `If-None-Match`; `GET /api/health`. `seed.ts` — детерминированный генератор: 4 дивизиона →
3–4 отдела → 2–4 команды (≥ 40 узлов, 3 уровня; осмысленные русские названия). `OrgStore`: приватный массив,
`snapshot(): { nodes, version }` отдаёт копию. Конфиг env через zod с человекочитаемой ошибкой (`PORT`, `MOCK_DEBUG`).
Отладочные параметры только при `MOCK_DEBUG=1`: `?delay=ms`, `?fail=1`, `?empty=1`, `?invalid=1` — для демонстрации
состояний и скриншотов. Сервер валидирует собственный ответ той же схемой в тестах.

**1.4 Модель дерева (`entities/org`).** `buildModel(nodes, version, prev?)` → `byId`, `childrenOf`, `depthOf`
(агрегаты добавятся на шаге 2, место в типе закладываем сразу). Проверка целостности: дубликат `id`, сирота, цикл →
`IntegrityError`. Дети сортируются по имени (`Intl.Collator('ru')`). Тесты: построение, три вида нарушений,
переиспользование объектов из `prev`, одинаковая версия → та же ссылка.

**1.5 Слой API и запрос.** `shared/api/fetchOrgTree({ signal })` → `HttpError | ValidationError`; `useOrgModel()` —
`useQuery` c `staleTime: 5_000`, `structuralSharing: false`, `retry: 1`, версия из `ETag`. `QueryClientProvider`
в `app/`. Тест `fetchOrgTree` на моках `fetch`: ok, 500, невалидный JSON/схема, abort.

**1.6 Тема и примитивы.** `app/theme` (токены, `motion`-хелпер, типизация `DefaultTheme`), `GlobalStyle`,
layout «шапка + панель», `shared/ui`: `Button`, `Spinner`, `Skeleton`, `StateMessage`.

**1.7 UI-стор.** `shared/lib/createStore` (`useSyncExternalStore` + селектор), `features/org-tree/treeUiStore`:
`expanded: Set<Id>`, `toggle`, `expandAll`, `collapseAll`, инициализация «корни раскрыты → виден второй уровень».
Тесты стора.

**1.8 Дерево.** `features/org-tree`: `OrgTree` (`role="tree"`), `TreeNode` (`treeitem`, `aria-expanded`,
`aria-level`, вложенный `ul[role=group]`), каждый узел подписан на своё `isOpen` селектором → `memo` реально работает.
Строка узла: шеврон (lucide, `aria-hidden`), `name`, headcount («N чел»), индикатор performance (цвет по порогам +
число). Кнопки «Свернуть все / Развернуть все». Клавиатура дерева: ↑/↓, →/← (раскрыть/свернуть/к родителю),
Home/End, Enter/Space — roving tabindex. Раскрытие пока мгновенное (анимация — шаг 3, но разметку под
`grid-template-rows` закладываем сразу).

**1.9 Состояния.** Скелетон при первой загрузке; ошибка (разные тексты для сети/валидации/целостности) с
«Повторить» без мигания полноэкранного лоадера; пустой ответ; фоновая ошибка при имеющихся данных — ненавязчивая
плашка. Тесты компонента-переключателя состояний.

**1.10 Docs.** README (запуск: `npm i && npm run dev`), заготовки `docs/architecture.md` и `docs/data-model.md`,
скриншоты состояний в `docs/screenshots/`.

**Приёмка**
- [ ] `npm run dev` поднимает клиент и сервер одной командой; импорты через `@/`
- [ ] ≥ 40 узлов, 3 уровня; невалидный ответ (`?invalid=1`) и нарушение целостности → экран ошибки
- [ ] Повторный маунт в пределах 5 с не даёт запроса; после — SWR-ревалидация, при той же версии ререндера нет
- [ ] Размонтирование во время запроса отменяет его (`?delay=3000`, вкладка Network → canceled)
- [ ] Второй уровень открыт по умолчанию; ветви раскрываются/скрываются мышью и с клавиатуры
- [ ] Узел: name, headcount, цветовой индикатор performance; в коде нет `style=`; линтер это гарантирует
- [ ] Бандл измерен (`npm run size`) и записан в README

## Шаг 2. Core — `step/2-core`

Цель: агрегаты, таблица, сортировка, фильтр, связь таблица → дерево.

**2.1 Агрегация (ADR 003).** `computeAggregates` внутри `buildModel`: проход по убыванию глубины, аддитивный
`Aggregate { headcount, budget, perfWeight, avgPerformance }`. **Обязательный unit-тест**: лист, узел с
потомками на 3 уровнях, взвешенность (большая команда перевешивает маленькую), `headcount = 0` → `null`,
собственные показатели узла входят в сумму, несколько корней. Тест «один расчёт на загрузку»: повторный рендер и
ревалидация с той же версией не вызывают `computeAggregates` (spy).

**2.2 Форматирование.** `shared/lib/format`: `formatBudget` → `12 345 678 руб.` (`Intl.NumberFormat('ru-RU')`,
неразрывные пробелы; тест с нормализацией пробелов), `formatPercent`, `levelLabel(depth)` → дивизион / отдел /
команда (глубже — «уровень N»).

**2.3 Строки таблицы.** `features/org-table/selectRows(model, { sort, filter })` — чистая функция + `useMemo`:
строка = узел + агрегат + уровень. Без сортировки — порядок обхода дерева (DFS) с отступом по уровню, как в макете;
при активной сортировке — плоский список без отступов. Сравнение строк через `Intl.Collator('ru')`, чисел — с
`null` в конце. Тесты.

**2.4 Таблица.** Нативный `<table>`, липкая шапка, скролл внутри панели. Столбцы: Подразделение, Уровень,
Всего сотрудников, Бюджет суммарный, Средняя эффективность (цвет + число; по наведению/фокусу — тултип с
собственным бюджетом узла, как в макете). `shared/ui/Tooltip` — свой, CSS + `aria-describedby`.

**2.5 Сортировка → ADR 006.** Клик по заголовку — по возрастанию, двойной клик — по убыванию (два `click` внутри
`dblclick` идемпотентно ставят asc, затем `dblclick` ставит desc — без таймеров и гонок). Клавиатура: Enter — asc,
Shift+Enter — desc. `aria-sort`, иконка направления. Кнопка сброса к порядку дерева. Тесты поведения.

**2.6 Фильтр.** Поле поиска в шапке; `shared/lib/useDebouncedValue(250)`; регистронезависимое вхождение в `name`;
ввод не блокируется (input управляется мгновенным значением, фильтрация — отложенным). Пустой результат →
состояние «ничего не найдено» с кнопкой очистки. Тест хука на fake timers.

**2.7 Выделение.** `selectedId` в ui-store. Клик по строке (и Enter — шаг 3) → узел в дереве: раскрыть всех
предков, выделить (`aria-selected`), `scrollIntoView({ block: 'nearest' })`, в узком режиме — переключиться на
вкладку «Дерево». Клик по узлу дерева симметрично выделяет строку таблицы.

**2.8 Layout.** `≥ 1280px` — split-view (таблица | дерево); ниже — переключатель «Таблица / Дерево» в шапке
(`role="tablist"`). Режим — в ui-store; через `matchMedia`, без ресайз-листенеров.

**2.9 Docs.** `docs/data-model.md`: модель, алгоритм агрегации, инвариант; ADR 006; README; скриншоты.

**Приёмка**
- [ ] Суммы включают сам узел и всех потомков; средняя взвешена по headcount — подтверждено тестами
- [ ] Агрегация выполняется один раз на версию данных (тест со spy)
- [ ] Сортировка по каждому столбцу, двойной клик — обратная; фильтр с дебаунсом 250 мс
- [ ] Клик по строке выделяет и показывает узел в дереве (в т.ч. в свернутой ветке)
- [ ] Бюджет в формате `12 345 678 руб.`; split-view на ≥ 1280px, переключатель — ниже

## Шаг 3. Polish — `step/3-polish`

Цель: live-обновления, инкрементальный пересчёт, индикатор соединения, клавиатура, анимации.

**3.1 Контракт WS (ADR 004).** В `packages/contracts`: `ServerMessageSchema` (discriminated union `hello | patch |
reset | ping`). Тесты схем.

**3.2 Сервер.** `@fastify/websocket` на `/ws`: `hello` при подключении, broadcast `patch`, `ping` каждые 15 с.
`OrgStore.mutate(changes)` → `version + 1`, событие для рассылки; `snapshot()` атомарен (версия и тело не
расходятся даже с `?delay`). Тикер (`TICK_INTERVAL_MS`, 1–3 узла за тик, значения в границах схемы).
Dev-эндпоинт `POST /api/debug/drop-connections` при `MOCK_DEBUG=1`. Тесты стора и тикера (инъекция random/clock).

**3.3 `applyPatch` (ADR 003).** Дельта вверх по предкам, одна поверхностная копия индексов на патч, нулевая
дельта → та же ссылка модели, неизвестный `id` → `null` (сигнал к рефетчу). Тесты: **инкремент ≡ полный пересчёт**
на случайных последовательностях патчей (seeded random), идентичность незатронутых объектов, затронуты ровно
узел и его предки.

**3.4 Backoff.** `shared/lib/backoff`: `nextDelay(attempt, { base, cap, random })` — full jitter, чистая функция;
тесты на границы, рост, cap.

**3.5 Клиент соединения.** `features/connection/createLiveConnection({ url, onMessage, onStatus })` —
конечный автомат `connecting | open | reconnecting | offline`, heartbeat-таймаут 35 с, сброс попыток после 5 с
стабильной работы, реакция на `online/offline`, `dispose()`. Хук `useLiveUpdates()` монтируется один раз в `app/`:
таблица решений из ADR 004 (`hello`/`patch`/`reset`/разрыв версий). Тесты автомата на fake timers и фейковом
WebSocket; тест «патч с версией +1 → `setQueryData`, разрыв → `invalidateQueries`, дубликат → игнор».

**3.6 Индикатор соединения.** В шапке, `role="status"`: подключено / подключение (спиннер lucide) / нет связи +
обратный отсчёт до попытки и кнопка «Подключиться сейчас».

**3.7 Подсветка обновлений.** Ячейки таблицы и метрики узла дерева: `@keyframes` fade ~1.5 с, перезапуск через
`key` от значения; срабатывает только на изменения от патча, не на первую отрисовку и не на сортировку/фильтр.
Предки затронутого узла подсвечиваются в агрегатных столбцах — наглядная демонстрация пересчёта вверх.

**3.8 Клавиатура таблицы.** Roving tabindex по строкам: ↑/↓, Home/End, Enter — выделить узел в дереве (= клик);
PageUp/PageDown — бонус. Фокус переживает сортировку/фильтр/патч (привязан к `id`, не к индексу);
`scrollIntoView({ block: 'nearest' })`. Тесты поведения.

**3.9 Анимация дерева.** Transition высоты через `grid-template-rows: 0fr ↔ 1fr`, поворот шеврона; свёрнутая
ветка недоступна для фокуса (`inert`); «Развернуть все» не тормозит. Всё под `prefers-reduced-motion: no-preference`.

**3.10 Docs.** `docs/architecture.md` (поток: HTTP-снимок → модель → патчи → UI), `docs/data-model.md`
(контракт WS-патча, таблица решений по версиям), GIF live-обновлений и обрыва соединения.

**Приёмка**
- [ ] Во вкладке Network при работающем WS нет повторных `GET /api/org-tree`; после обрыва и расхождения версий — ровно один
- [ ] Патч меняет ссылки только у узла и его предков (тест) → ререндерятся только их строки (React Profiler)
- [ ] Обновлённые ячейки гаснут ~1.5 с; при `prefers-reduced-motion` анимаций нет
- [ ] Остановка сервера → индикатор «нет связи», задержки растут экспоненциально до cap; запуск → авто-восстановление
- [ ] Таблица полностью управляется с клавиатуры: стрелки, Home/End, Enter
- [ ] Размонтирование закрывает сокет и таймеры (тест)

## Шаг 4. Bonus — `step/4-bonus`

Цель: прод-окружение одной командой и AI-поиск с fallback.

**4.1 Прод-сборка сервера.** esbuild → `apps/server/dist/index.js` (контракты вбандлены); `start` запускает именно
его. Env через zod: `PORT`, `TICK_INTERVAL_MS`, `MOCK_DEBUG`, `ANTHROPIC_API_KEY?`, `AI_MODEL`, `AI_TIMEOUT_MS`.

**4.2 Docker.** `apps/server/Dockerfile` (multi-stage, `node:22-alpine`, non-root), `apps/client/Dockerfile`
(сборка → `nginx:alpine`), `docker-compose.yml` (`client` публикует порт, `server` только во внутренней сети,
healthcheck), `.env.example`, `.dockerignore`. `docker-compose up` → приложение на `http://localhost:8080`.

**4.3 Nginx → ADR 008.** Статика с `gzip on` + `gzip_static` (пре-сжатие при сборке), `Cache-Control: immutable`
для хэшированных ассетов и `no-cache` для `index.html`, SPA-fallback; прокси `/api` (ETag не срезается) и `/ws`
(`Upgrade`, `proxy_read_timeout` > интервала ping). Проверка: `curl -H 'Accept-Encoding: gzip' -I`.

**4.4 Бюджет бандла.** `npm run size` ≤ 200 КБ gzip — в README с фактическими цифрами. Если тесно: `zod/mini`,
ревизия импортов lucide, отключение лишнего в react-query.

**4.5 AI-поиск → ADR 007.** Контракт `SearchFilterSchema`: `{ name?, levels?, headcount?: {min,max}, budget?:
{min,max}, performance?: {min,max}, sort?: { column, direction } }` — фильтр по **агрегированным** значениям
таблицы. Сервер: `POST /api/search/parse { query }` → Claude API (быстрая модель, structured output по JSON-схеме
из zod, системный промпт с описанием столбцов и примерами), таймаут, валидация ответа, в ответе `source: 'ai'`.
Нет ключа / ошибка / таймаут / невалидный ответ → `source: 'fallback'`. Ключ — только в env сервера.
Перед реализацией — загрузить skill `claude-api` (актуальные id моделей и параметры).

**4.6 Клиент AI-поиска.** Та же строка поиска: текстовый фильтр работает мгновенно (дебаунс 250 мс), AI-разбор
запускается по Enter/кнопке (`useMutation`, отмена предыдущего через `signal`), применённый фильтр показывается
чипами с возможностью снять каждый; индикатор «AI применён» (зелёный, как в макете) / «обычный поиск».
`applySearchFilter(rows, filter)` — чистая функция с тестами. Примеры запросов в плейсхолдере:
«отделы с бюджетом больше 50 млн и эффективностью ниже 60».

**4.7 Сдача.** README: запуск одной командой (dev и docker), раздел «AI в разработке» из `docs/ai-log.md`,
размер бандла, скриншоты/GIF. Финальная вычитка `docs/architecture.md`, `docs/data-model.md`, индекса ADR.

**Приёмка**
- [ ] Чистая машина: `cp .env.example .env && docker-compose up` → рабочее приложение с live-обновлениями через Nginx
- [ ] Ответы статики сжаты gzip; прод-сборка ≤ 200 КБ gzip
- [ ] Естественно-языковой запрос превращается в структурированный фильтр; без ключа и при сбое — текстовый поиск
- [ ] Ключ AI не попадает ни в клиентский бандл, ни в образ клиента
- [ ] Комплект сдачи полон: README, architecture, data-model, ADR, тест агрегации, скриншоты/GIF

## Риски и заранее известные грабли

| Риск | Что делаем |
| --- | --- |
| `replaceEqualDeep` react-query не спускается в `Map` → модель заменяется целиком | `structuralSharing: false`, идентичность в `buildModel`/`applyPatch` (ADR 002) |
| `memo(TreeNode)` бесполезен, если вниз передаётся `Set` раскрытых узлов | подписка узла на своё `isOpen` через селектор стора (1.7–1.8) |
| react-query v5: повтор запроса без данных сбрасывает статус в `pending` → мигает лоадер на экране ошибки | состояние ошибки держим сами, ориентируемся на `isFetching` (ADR 002, п. 7) |
| Заголовок версии пишется до `?delay`, тело — после → расхождение при работающем тикере | атомарный `snapshot()` после задержки (3.2) |
| `tsc --noEmit` в `build` сервера ничего не эмитит → Docker не стартует | esbuild-бандл с шага 4.1, `typecheck` отдельно |
| Двойной клик порождает два `click` | идемпотентная схема asc/desc (2.5, ADR 006) |
| Скрытые узлы свёрнутой ветки ловят фокус | `inert` + roving tabindex |
| Бюджет 200 КБ (React + styled-components + react-query + zod) | `npm run size` с шага 1, цифры в README на каждом шаге |
| «Один коммит на этап» vs атомарные коммиты в ветке | решает автор при мердже: squash или тег на merge-коммит |
