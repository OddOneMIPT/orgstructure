# План реализации

Задание: `task/task.md`. Макет: `task/design.drawio.xml`. Решения: `docs/adr/`. Правила: `CLAUDE.md`.

## Как работаем

```
main ── step/0-conventions ── step/1-foundation ── step/2-core ── step/3-polish ── step/4-bonus
```

- Каждая ветка создаётся от предыдущей; внутри — атомарные коммиты. Автор полирует, мерджит в `main`
  и ставит тег `step/N` (задание: «каждый этап — отдельный коммит с тегом» → при мердже шаг сквошится
  или тегируется merge-коммит — на усмотрение автора).
- Задачи внутри шага идут в указанном порядке: сначала чистая логика с тестами, потом UI.
- Каждая задача заканчивается записью в `docs/ai-log.md`.
- Шаг закрыт = выполнен чек-лист «Приёмка» + зелёные `typecheck`, `lint`, `test`, `build`, `size`.
- `docs/architecture.md` и `docs/data-model.md` в конце каждого шага доводятся до состояния «полно для
  текущего объёма», а не остаются заглушками до шага 3: если работа встанет раньше, обязательные документы
  всё равно будут готовы.

Продукт по макету: приложение «Бюджетница», один экран. Шапка: заголовок, индикатор соединения (слева, сразу
за заголовком), строка поиска (справа). Слева таблица (ширина ≈670), справа дерево (≈330) с шапкой колонок
«Подразделение · Эффективность · Штат» и кнопками «Свернуть все / Развернуть все»; у панелей собственный
скролл, страница не скроллится. Ниже 1280px — одна панель и переключатель «Таблица / Дерево» в шапке.

## Шаг 1. Foundation — `step/1-foundation`

Цель: монорепо, mock-API, валидируемый кэшируемый запрос, интерактивное дерево, три состояния.

**1.1 Scaffold монорепо.** Корневой `package.json` (workspaces, скрипты `dev/test/lint/typecheck/build/size`),
`tsconfig.base.json`: `strict`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`,
**`moduleResolution: "bundler"` во всех трёх пакетах** (при `nodenext` `tsc` не примет `.ts` в `exports`
контрактов) + `paths` для `@/` и `@org/contracts`. Версии: **TypeScript 5.9.3** (7.x не поддерживается
`typescript-eslint`) и **ESLint 10.x** — актуальная ветка доступна ровно потому, что `eslint-plugin-react`
мы не используем (ADR 001). ESLint flat: typescript-eslint 8 с
`projectService: true` (в проект обязан попадать и `packages/contracts/src`), eslint-plugin-react-hooks,
запрет inline-CSS правилом ядра `no-restricted-syntax` (`JSXAttribute[name.name='style']`), запрет
направлений импорта (`no-restricted-imports`). Prettier. Vitest через `test.projects`: клиент — `jsdom` +
`test/setup.ts` (заглушки `matchMedia` и `Element.prototype.scrollIntoView`, которых в jsdom нет и вызов
которых бросает), сервер и контракты — `node`. `apps/client` — Vite + React 19 + TS, dev-прокси `/api` и
`/ws` (`ws: true`; путь `/` не проксируем — там HMR-сокет Vite). `scripts/size.mjs` — gzip-сумма JS+CSS,
порог 200 КБ.

**1.2 Контракты.** `packages/contracts`: `OrgNodeSchema` (`id`, `name`, `parentId: string | null`, `headcount`
int ≥ 0, `budget` int ≥ 0, `performance` 0–100, `updatedAt` ISO) — **`.strict()`**: лишние поля это ошибка
(zod по умолчанию молча срезает их, а задание требует «невалидный ответ — ошибка»). `OrgTreeResponseSchema`.
Тесты: валидный, лишнее поле → ошибка, performance вне диапазона, не массив.

**1.3 Сервер.** Fastify: `GET /api/org-tree` → плоский массив, `ETag: "<epoch>.<version>"` (`epoch` — uuid
запуска процесса), `Cache-Control: no-cache`, ответ `304` по `If-None-Match`; `GET /api/health`.
`seed.ts` — **детерминированный** генератор: seeded PRNG (не `Math.random`) и фиксированная базовая метка
времени (не `new Date()`), иначе каждый старт даёт другие данные и ломает тесты и скриншоты. 4 дивизиона →
3–4 отдела → 2–4 команды, осмысленные русские названия. `OrgStore`: приватный массив,
`snapshot(): { nodes, epoch, version }` отдаёт копию. Конфиг env через zod с человекочитаемой ошибкой.
Отладочные параметры только при `MOCK_DEBUG=1`: `?delay=ms`, `?fail=1`, `?empty=1`, `?invalid=1`.
Тесты: сервер валидирует собственный ответ той же схемой; узлов **≥ 48** (нижняя граница диапазона даёт
ровно 40 — впритык к «минимум 40»), глубина ≥ 3, нет сирот и циклов.

**1.4 Модель дерева (`entities/org`).** `buildModel(nodes, revision, prev?)`, `revision = { epoch, version }`
→ `byId`, `childrenOf`, `depthOf`, `ancestorsOf` (агрегаты — шаг 2, место в типе закладываем сразу).
**Проверка ревизии — первая строка функции**, возврат `prev` до проверки целостности и до агрегации, иначе
обещание «агрегация один раз» не выполняется. Целостность: дубликат `id`, сирота, цикл → `IntegrityError`;
пустой массив — **не** нарушение, `[]` даёт пустую модель. Дети сортируются `Intl.Collator('ru')`.
Тесты: построение, три вида нарушений, пустой ответ, переиспользование объектов из `prev`, одинаковая
ревизия → та же ссылка, та же версия при другой эпохе → новая модель.

**1.5 Слой API и запрос.** `shared/api/fetchOrgTree({ signal, prev })`: `304` обрабатывается **до**
`res.ok` (у 304 `ok === false`); парсер ревизии терпит слабый ETag `W/"…"`; нет ETag → ревизия неизвестна
(патчи потом не применяются, ADR 002). Ошибки: `HttpError | ValidationError | IntegrityError`.
`useOrgModel()` — `useQuery` со `staleTime: 5_000`, `retry: 1`; **`structuralSharing: false` задаётся в
`defaultOptions.queries`**, а не в хуке (патч может прийти до монтирования). `prev` берётся из
`queryClient.getQueryData(orgTreeKey)` внутри `queryFn`. Защита от отката:
`if (prev && prev.epoch === rev.epoch && rev.version < prev.version) return prev`.
Тесты на моках `fetch`: ok, 500, невалидный JSON/схема, abort, 304, слабый ETag, отсутствие ETag,
ответ со старой версией.

**1.6 Тема и примитивы.** `shared/config/theme` (токены, `motion`-хелпер, типизация `DefaultTheme`), `GlobalStyle`,
layout «шапка + панель», `shared/ui`: `Button`, `PerformanceBar`, `Spinner`, `Skeleton`, `StateMessage`,
`VisuallyHidden`. `PerformanceBar` — дорожка с заливкой (`$pct`, `transform: scaleX`) + число,
`role="meter"`; один компонент на дерево и таблицу.

**1.7 UI-стор.** `shared/lib/createStore` (`useSyncExternalStore` + селектор), `features/org-tree/treeUiStore`:
`expanded: Set<Id>`, `toggle`, `expandAll`, `collapseAll`. Инициализация — **раскрыты корни**, то есть
видно два уровня: дивизионы и отделы. Команды раскрывает пользователь. В README одна строка об этом
прочтении. Тесты стора.

**1.8 Дерево.** `features/org-tree`: `OrgTree` (`role="tree"`), `TreeNode` (`treeitem`, `aria-expanded`,
`aria-level`, вложенный `ul[role=group]`), каждый узел подписан на своё `isOpen` селектором → `memo`
реально работает. Над деревом — шапка колонок; строка узла (grid, по макету): шеврон + имя ·
`PerformanceBar` · штат («3 чел»; суммарное число добавится на шаге 2). Ветка переключается кликом по всей
строке, шеврон остаётся отдельной кнопкой ради клавиатуры и гасит всплытие. Кнопки «Свернуть все /
Развернуть все». Клавиатура — **шаг 3**; здесь только фокусируемые шевроны и Enter/Space. Разметку под
`grid-template-rows` закладываем сразу, анимация — шаг 3.

**1.9 Состояния.** Скелетон при первой загрузке; ошибка (разные тексты для сети/валидации/целостности) с
«Повторить»; пустой ответ; фоновая ошибка при имеющихся данных — ненавязчивая плашка. Экран ошибки держит
**последнюю ошибку в `ref`**: повтор без данных обнуляет в react-query и `status`, и `error`, поэтому
рисуем по `lastError && !data`, а `isFetching` управляет только спиннером в кнопке. Тесты переключателя
состояний.

**1.10 Docs.** README (запуск, прочтение «второго уровня», размер бандла), `docs/architecture.md` и
`docs/data-model.md` — полные для текущего объёма, скриншоты состояний в `docs/screenshots/`.

**Приёмка**

- [x] `npm run dev` поднимает клиент и сервер одной командой; импорты через `@/`
- [x] 61 узел (4/15/42), 3 уровня; `?invalid=1` и нарушение целостности → экран ошибки; `?empty=1` → пустое состояние
- [x] Повторный маунт в пределах 5 с не даёт запроса; после — ревалидация, и при той же ревизии возвращается прежняя модель (тесты `useOrgModel`)
- [x] Размонтирование во время запроса отменяет его — тест `OrgDashboard` проверяет, что `signal` действительно прерван
- [x] По умолчанию видно два уровня (раскрыты корни); ветви раскрываются/скрываются мышью
- [x] Узел: имя, штат, полоса эффективности с числом; в коде нет `style=` — линтер это гарантирует
- [x] Бандл измерен: 379 КБ raw → 117 КБ gzip (58% бюджета), записан в README

## Шаг 2. Core — `step/2-core`

Цель: агрегаты, таблица, сортировка, поиск по обоим представлениям, связь таблица ↔ дерево.

**2.1 Агрегация (ADR 003).** `computeAggregates` внутри `buildModel`: проход по убыванию глубины, аддитивный
`Aggregate { headcount, budget, perfWeight, avgPerformance }`. **Обязательный unit-тест**: лист, узел с
потомками на 3 уровнях, взвешенность (большая команда перевешивает маленькую), `headcount = 0` → `null`,
собственные показатели узла входят в сумму, несколько корней. Тест «один расчёт на загрузку»: повторный
рендер и ревалидация с той же ревизией не вызывают `computeAggregates` (spy) — работает благодаря раннему
возврату из 1.4.

**2.2 Форматирование.** `shared/lib/format`: `formatBudget` → `12 345 678 руб.` (`Intl.NumberFormat('ru-RU')`),
`formatPercent`, `formatStaff(own, total)` → «3 / 128» с расшифровкой в `aria-label`, `levelLabel(depth)` →
дивизион / отдел / команда (глубже — «уровень N»; в макете такого случая нет, это наше расширение).
Неразрывные пробелы (U+00A0 / U+202F) нормализуются и в unit-тестах, и в проверках отрисованного текста.

**2.3 Фильтр и строки (чистые функции в `entities/org`).** `selectFilteredView(model, predicate)` →
`{ matched, visible }`, где `visible = matched ∪ ancestors(matched)` — путь до совпадения не рвётся; тот же
обход вверх, что у агрегации. `splitByMatch(name, query)` → части для `<mark>`.
`features/org-table/selectRows(model, view, { sort })`: без сортировки — порядок обхода дерева (DFS) с
отступом по уровню, как в макете; при активной сортировке — плоский список. `Intl.Collator('ru')` для строк,
`null` в конец для чисел. Тесты на всё.

**2.4 Таблица.** Нативный `<table>`, липкая шапка, скролл внутри панели. Столбцы: Подразделение, Уровень,
Всего сотрудников, Бюджет суммарный, Средняя эффективность (`PerformanceBar`). Иконка сортировки у всех
пяти заголовков, `user-select: none` на `th`.

**2.5 Сортировка → ADR 006.** Клик по заголовку — по возрастанию, двойной клик — по убыванию (два `click`
внутри `dblclick` идемпотентно ставят asc, затем `dblclick` ставит desc — без таймеров и гонок).
Клавиатура: Enter — asc, Shift+Enter — desc. `aria-sort`, иконка направления. Кнопка сброса к порядку
дерева. Тесты поведения.

**2.6 Поиск.** Поле в шапке; `shared/lib/useDebouncedValue(250)`; регистронезависимое вхождение в `name`.
Фильтр применяется **и к таблице, и к дереву**: в дереве остаются совпадения и их предки, ветки на пути к
совпадениям раскрыты принудительно (`effectiveExpanded = expanded ∪ ancestors(matched)`, набор пользователя
не мутируется и возвращается после сброса). Совпавшие фрагменты имени подсвечиваются `<mark>` в обоих
представлениях. Ввод не блокируется (input — мгновенное значение, фильтрация — отложенное). Пустой результат
→ «ничего не найдено» с кнопкой очистки. Тест хука на fake timers.

**2.7 Выделение.** `selectedId` в ui-store. Клик по строке → узел в дереве: раскрыть предков, выделить
(`aria-selected`), `scrollIntoView({ block: 'nearest' })` **следующим кадром** после раскрытия (иначе строка
ещё нулевой высоты и прокрутка попадёт мимо); в узком режиме — переключиться на вкладку «Дерево». Клик по
узлу дерева симметрично выделяет строку. Тултип на индикаторе эффективности узла дерева: собственный бюджет
узла и время `updatedAt` (`shared/ui/Tooltip`, CSS + `aria-describedby`).

**2.8 Layout.** `≥ 1280px` — split-view (таблица | дерево); ниже — переключатель «Таблица / Дерево»
(`role="tablist"`). Режим — в ui-store, через `matchMedia` за тонкой обёрткой `shared/lib/useMediaQuery`
(инжектируемой в тестах), без ресайз-листенеров.

**2.9 Docs.** `docs/data-model.md`: модель, алгоритм агрегации, инвариант, правило фильтрации; ADR 006;
README; скриншоты.

**Приёмка**

- [ ] Суммы включают сам узел и всех потомков; средняя взвешена по headcount — подтверждено тестами
- [ ] Агрегация выполняется один раз на ревизию данных (тест со spy)
- [ ] Сортировка по каждому столбцу, двойной клик — обратная; поиск с дебаунсом 250 мс
- [ ] Поиск фильтрует оба представления, дерево не теряет путь до совпадения, совпадения подсвечены
- [ ] Клик по строке выделяет и показывает узел в дереве (в т.ч. в свёрнутой ветке)
- [ ] Бюджет в формате `12 345 678 руб.`; штат узла — «3 / 128»; split-view на ≥ 1280px

## Шаг 3. Polish — `step/3-polish`

Цель: live-обновления, инкрементальный пересчёт, индикатор соединения, клавиатура, анимации.

**3.1 Контракт WS (ADR 004).** В `packages/contracts`: `ServerMessageSchema` (discriminated union
`hello | patch | reset | ping`, каждое с `epoch`). Тесты схем.

**3.2 Сервер.** `@fastify/websocket` 11 на `/ws`, обработчик `(socket, req)`; отдельный не-WS `GET /ws` не
регистрируем. `hello` при подключении, broadcast `patch`, `ping` каждые 15 с; лог на апгрейд по неизвестному
пути. `OrgStore.mutate(changes)` → `version + 1` и событие для рассылки; `snapshot()` атомарен (версия и
тело не расходятся даже с `?delay`). Тикер (`TICK_INTERVAL_MS`, 1–3 узла за тик, значения в границах схемы).
Dev-эндпоинт `POST /api/debug/drop-connections` при `MOCK_DEBUG=1`. Тесты стора и тикера (инъекция
random/clock).

**3.3 `applyPatch` (ADR 003).** Дельта вверх по предкам, одна поверхностная копия индексов на патч, нулевая
дельта → та же ссылка модели, неизвестный `id` → `null`. Тесты: **инкремент ≡ полный пересчёт** на
случайных последовательностях патчей (seeded random), идентичность незатронутых объектов, затронуты ровно
узел и его предки.

**3.4 Backoff.** `shared/lib/backoff`: `nextDelay(attempt, { base, cap, random })` — full jitter, чистая
функция; тесты на границы, рост, cap.

**3.5 Клиент соединения.** `features/connection/createLiveConnection({ url, socketFactory, onMessage,
onStatus })` — конечный автомат `connecting | open | reconnecting | offline`, heartbeat-таймаут 35 с, сброс
счётчика попыток после 5 с стабильной работы, реакция на `online/offline`, `dispose()`. WebSocket
инжектится фабрикой, а не подменой глобала (он есть и в Node 22, и в jsdom). Хук `useLiveUpdates()`
монтируется один раз в `app/` и реализует таблицу решений ADR 004; порядок проверок: нет модели → неизвестная
ревизия → эпоха → номер версии. **Результат `applyPatch` проверяется до записи**: `null` → инвалидация, в
`setQueryData` он попасть не должен. Инвалидация — `invalidateQueries({ queryKey }, { cancelRefetch: false })`
(опция во втором аргументе). Тесты автомата на fake timers и фейковом сокете; тест «патч +1 →
`setQueryData`, разрыв → `invalidateQueries`, дубликат → игнор, рестарт сервера с совпавшим номером версии
(другая эпоха) → `invalidateQueries` без применения патча, `hello` во время первой загрузки → ничего».

**3.6 Индикатор соединения.** В шапке, `role="status"`: подключено / подключение (спиннер lucide) / нет
связи + обратный отсчёт до попытки и кнопка «Подключиться сейчас».

**3.7 Подсветка обновлений.** Хук `useFlash(value)`: предыдущее значение в ref, фаза `'a' | 'b' | null`
(старт `null` → на первом рендере не мигает), фаза меняется только при реальном изменении **значения**
(не ссылки: патч `performance` создаёт новый `Aggregate` у всех предков). Ячейка рендерит `data-flash`, в CSS
два одинаковых `@keyframes` под разными именами — перезапуск без размонтирования, фокус строки и
`aria-selected` выживают. Предки затронутого узла подсвечиваются в агрегатных столбцах — наглядная
демонстрация пересчёта вверх. Под `prefers-reduced-motion: reduce` подсветки нет (осознанно, ADR 005).

**3.8 Клавиатура.** Общий хук roving tabindex — для таблицы и для дерева.
Таблица: ↑/↓, Home/End, Enter — выделить узел в дереве. Дерево: ↑/↓, →/← (раскрыть / свернуть / к родителю),
Home/End, Enter/Space. Фокус привязан к `id`, а не к индексу, и переживает сортировку, фильтр и патч;
`scrollIntoView({ block: 'nearest' })`. Тесты поведения.

**3.9 Анимация дерева.** `grid-template-rows: 0fr ↔ 1fr`, у внутреннего блока **`min-height: 0`** и
`overflow: hidden`, нулевые padding/margin/border у анимируемой обёртки. Поворот шеврона. `inert`
выставляется **синхронно из состояния** (не по `transitionend`: событие не приходит при reduced-motion, во
вложенной свёрнутой ветке и в jsdom). «Развернуть все» / «Свернуть все» выполняются без анимации
(`data-animate="off"` на корне дерева на один кадр). Всё под `prefers-reduced-motion: no-preference`.

**3.10 Docs.** `docs/architecture.md` (поток: HTTP-снимок → модель → патчи → UI), `docs/data-model.md`
(контракт WS-патча, таблица решений по ревизиям), GIF live-обновлений и обрыва соединения.

**Приёмка**

- [ ] При работающем WS нет повторных `GET /api/org-tree`; после обрыва и расхождения ревизий — ровно один
- [ ] Патч меняет ссылки только у узла и его предков (тест) → перерисовываются только их строки (Profiler)
- [ ] Обновлённые ячейки гаснут ~1.5 с и **не** мигают при первой загрузке, сортировке, фильтре и смене вкладки
- [ ] При `prefers-reduced-motion` нет ни анимации раскрытия, ни подсветки; раскрытие работает
- [ ] Рестарт сервера (обнуление версий) не даёт тихого расхождения: новая эпоха → один рефетч
- [ ] Остановка сервера → индикатор «нет связи», задержки растут экспоненциально до cap; запуск → авто-восстановление
- [ ] Таблица и дерево полностью управляются с клавиатуры; скрытые узлы свёрнутой ветки не ловят фокус
- [ ] Размонтирование закрывает сокет и таймеры (тест)

## Шаг 4. Bonus — `step/4-bonus`

Цель: прод-окружение одной командой и AI-поиск с fallback.

**4.1 Прод-сборка сервера.** esbuild → `apps/server/dist/index.js`; внешние зависимости перечисляются
**явно** (обычный `--packages=external` вынес бы и `@org/contracts`, и Node упал бы на импорте `.ts`),
в `build` — smoke `node dist/index.js`. `start` запускает именно бандл. Env через zod: `PORT`,
`TICK_INTERVAL_MS`, `MOCK_DEBUG`, `ANTHROPIC_API_KEY?`, `AI_MODEL`, `AI_TIMEOUT_MS`.

**4.2 Docker.** `apps/server/Dockerfile` (multi-stage, `node:22-alpine`, non-root), `apps/client/Dockerfile`
(сборка → `nginx:alpine`), `docker-compose.yml` (v2-синтаксис, без ключа `version:`; `client` публикует порт,
`server` только во внутренней сети, healthcheck). **Дефолты живут в самом compose-файле**, `.env.example` —
только для переопределений: `docker compose up` должен работать одной командой, без предварительного
копирования `.env`. `.dockerignore`.

**4.3 Nginx → ADR 008.** Статика с `gzip on` + `gzip_types` (без `gzip_static`: Vite не эмитит `.gz`, а
тянуть плагин пре-сжатия ради этого не стоит), `Cache-Control: immutable` для хэшированных ассетов и
`no-cache` для `index.html`, SPA-fallback; прокси `/api` (ETag не срезается; при сжатии проксируемого ответа
nginx делает его слабым — клиент это уже умеет) и `/ws` (`proxy_http_version 1.1`, `Upgrade/Connection`,
`proxy_read_timeout` > интервала ping). Проверка: `curl -H 'Accept-Encoding: gzip' -I`.

**4.4 Бюджет бандла.** `npm run size` ≤ 200 КБ gzip — в README с фактическими цифрами. По оценке
(React ≈ 60–65, react-query ≈ 12–14, styled-components ≈ 12–13, zod ≈ 13–14, иконки < 2, код 20–30) ожидаем
≈ 125–140 КБ, запас есть. Реальные риски — namespace-импорт из `lucide-react` вместо именованных; `zod/mini`
держим в уме как маловероятную крайнюю меру.

**4.5 AI-поиск → ADR 007.** Контракт `SearchFilterSchema`: `{ name?, levels?, headcount?: {min,max}, budget?:
{min,max}, performance?: {min,max}, sort?: { column, direction } }` — фильтр по **агрегированным** значениям.
Сервер: `POST /api/search/parse { query }` → Claude API (быстрая модель, structured output по JSON-схеме из
zod, системный промпт с описанием столбцов и примерами), таймаут, валидация ответа, `source: 'ai'`.
Нет ключа / ошибка / таймаут / невалидный ответ → `source: 'fallback'`. Ключ — только в env сервера.
Перед реализацией — загрузить skill `claude-api` (актуальные id моделей и параметры).

**4.6 Клиент AI-поиска.** Та же строка поиска: текстовый фильтр работает мгновенно (дебаунс 250 мс),
AI-разбор запускается по Enter/кнопке (`useMutation`, отмена предыдущего через `signal`). Полученный фильтр
подставляется в **тот же предикат**, что и текстовый поиск (2.3), поэтому автоматически действует и на
дерево, и на таблицу; подсветки `<mark>` при AI-фильтре нет — подсвечивать нечего. Применённый фильтр
показывается чипами со снятием каждого; индикатор «AI применён» (зелёный, как в макете) / «обычный поиск».
`applySearchFilter` — чистая функция с тестами. Примеры в плейсхолдере: «отделы с бюджетом больше 50 млн и
эффективностью ниже 60».

**4.7 Сдача.** README: запуск одной командой (dev и docker), раздел «AI в разработке» из `docs/ai-log.md`,
размер бандла, **скриншоты/GIF прямо в README**, а не только в `docs/screenshots/`. Финальная вычитка
`docs/architecture.md`, `docs/data-model.md`, индекса ADR (006, 007, 008 должны существовать). Проверить,
что теги `step/1…4` расставлены и каждый — предок финального коммита.

**Приёмка**

- [ ] Чистая машина: `docker compose up` одной командой → рабочее приложение с live-обновлениями через Nginx
- [ ] Ответы статики сжаты gzip; прод-сборка ≤ 200 КБ gzip
- [ ] Естественно-языковой запрос превращается в структурированный фильтр; без ключа и при сбое — текстовый поиск
- [ ] Ключ AI не попадает ни в клиентский бандл, ни в образ клиента
- [ ] Комплект сдачи полон: README со скриншотами, architecture, data-model, ADR 001–008, тест агрегации, теги `step/1…4`

## Риски и заранее известные грабли

| Риск                                                                                                                                                                                     | Что делаем                                                                                                          |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `applyPatch` вернул `null`, апдейтер `setQueryData` пропускает только `undefined` → в кэше `null` со статусом `success`, падение у первого читателя                                      | результат проверяется **до** записи в кэш (3.5, ADR 004)                                                            |
| Подсветка через `key`: смена ключа монтирует элемент, а маунт запускает CSS-анимацию → мигает всё при загрузке, смене вкладки и возврате строк после фильтра; плюс теряется фокус строки | `useFlash` с `data-flash` и двумя `@keyframes`, без размонтирования (3.7, ADR 005)                                  |
| `invalidateQueries({ cancelRefetch: false })` одним объектом — опция молча игнорируется, остаётся `cancelRefetch: true`, частый тикер перезапускает запрос                               | опции вторым аргументом (3.5, ADR 004)                                                                              |
| Рефетч в полёте отстаёт от применённых патчей → запись старой модели → «разрыв» → новый рефетч                                                                                           | сравнение ревизий в `queryFn`, ранний возврат `prev` (1.5, ADR 002)                                                 |
| Повтор запроса без данных обнуляет и `status`, и `error` → экран ошибки теряет текст                                                                                                     | последняя ошибка в `ref`, рендер по `lastError && !data` (1.9, ADR 002)                                             |
| `typescript@latest` = 7.x, не поддерживается `typescript-eslint` → типизированный линтинг не работает                                                                                    | пин TypeScript 5.9.3 (1.1, ADR 001)                                                                                 |
| `eslint-plugin-react` не поддерживает ESLint 10, а именно им запрещали inline-CSS                                                                                                        | плагин не используем вовсе: запрет `style` — правилом ядра `no-restricted-syntax`, ESLint берём 10.x (1.1, ADR 005) |
| `exports` на `.ts` не резолвится при `node16`/`nodenext` → падает `tsc`                                                                                                                  | `moduleResolution: "bundler"` + `paths` (1.1, ADR 001)                                                              |

| Массовое «развернуть все» — десятки вложенных анимируемых grid-контейнеров, джанк и неверная высота                                                                                      | `data-animate="off"` на время операции (3.9)                                                                        |
