# ADR 006. Сортировка таблицы и порядок строк

Статус: Принято · 2026-09-18

## Контекст

Задание: «Сортировка по любому столбцу, двойной клик — обратная». Формулировка необычная: привычнее
переключать направление одним кликом. Плюс в макете строки таблицы идут в порядке дерева и с отступом по
уровню — то есть порядок по умолчанию несёт структуру, а не произвольную сортировку.

Двойной клик в браузере порождает три события: `click`, `click`, `dblclick`. Значит, любая схема, где
одиночный клик **переключает** направление, при двойном клике сработает трижды и результат будет зависеть
от порядка обработки.

## Решение

1. **Клик — по возрастанию, двойной клик — по убыванию.** Буквально по заданию.
2. **«По возрастанию» идемпотентно**: повторный клик по той же колонке оставляет `asc` и не меняет
   состояние (возвращается прежний объект). Поэтому пара кликов внутри двойного безвредна, а пришедший
   следом `dblclick` спокойно переводит в `desc`. Ни таймеров, ни отложенной обработки клика не нужно.
3. **Клавиатура:** `Enter` — по возрастанию, `Shift+Enter` — по убыванию. Заголовок — настоящая кнопка.
4. **Порядок по умолчанию — обход дерева** (`sort === null`), с отступом по уровню: так строки читаются
   как структура. При активной сортировке структура всё равно нарушена, поэтому отступ убирается, а
   список становится плоским. Есть кнопка «Как в дереве», возвращающая исходный порядок.
5. **Узлы без данных** (пустое по людям поддерево → средняя эффективность `null`) всегда внизу, независимо
   от направления: их позиция вычисляется **до** применения знака направления.
6. Строки сравниваются `Intl.Collator('ru')`, уровень — по глубине с добором по имени.
7. `aria-sort` на активном заголовке, иконка направления, `user-select: none` (иначе двойной клик выделяет
   текст заголовка).

## Альтернативы

- **Клик переключает asc/desc (привычная схема).** Удобнее, но прямо расходится с формулировкой задания,
  а на двойном клике даёт гонку из трёх событий.
- **Откладывать обработку `click` на ~250 мс, чтобы отличить одиночный от двойного.** Классический приём,
  но он делает сортировку заметно «вязкой» и добавляет таймер в тестируемый путь. Идемпотентность решает
  ту же задачу без задержки.
- **Трёхтактный цикл asc → desc → без сортировки.** Ещё дальше от задания; сброс вынесен в отдельную кнопку.
- **Сохранять отступ при сортировке.** Выглядит знакомо, но вводит в заблуждение: отступ обещает иерархию,
  которой в отсортированном списке уже нет.
- **Отправлять `null` наверх при `desc`.** Формально «симметрично», но пустые значения вытесняют полезные
  строки с первого экрана.

## Последствия

- Состояние сортировки — один объект `{ column, direction } | null` в сторе таблицы; `null` это не «нет
  сортировки», а осмысленный режим «как в дереве».
- Поведение проверяется тестами именно как поведение: клик, двойной клик, повторный клик, сброс.
- Пользователь не может получить `desc` одним кликом — это цена буквального следования заданию; кнопка
  сброса и подсказка в `title` заголовка компенсируют неочевидность.
